# Архітектура агента

## 1. Проблеми, які вирішує агент

Агент створений для автоматизації базового процесу підготовки JavaScript-проєкту та його CI/CD-інфраструктури. Основні проблеми, які він вирішує:

- прискорення ініціалізації проєкту;
- стандартизація структури файлів і навичок;
- перевірка правильності базових кроків розробки;
- автоматизація побудови та тестування через npm і Jest;
- підготовка GitHub Actions workflow для різних ОС;
- мінімізація ризику помилок через послідовний оркестратор `init`.

## 2. Використовувані skills

Агент використовує такі навички:

- `project-scaffold`
- `build-and-test`
- `github-actions`

Ці навички описують основні етапи роботи:

- створення структури проєкту;
- налаштування збірки та тестування;
- підготовку CI-пайплайну для GitHub Actions.

## 3. Доступні користувачу commands

Користувач може викликати такі команди агента:

- `git-init`
- `create-project`
- `create-build`
- `create-actions`
- `check`
- `init`

Ці команди формують послідовний workflow для підготовки проєкту і перевірки його стану.

## 4. Потоки даних між етапами

Основна логіка потоку даних виглядає так:

`project_name` -> `src/` -> `package.json` / `scripts/build.js` -> `ci.sh` / `ci.bat` -> `ci.yml`

Це означає:

1. Спочатку визначається базовий параметр проєкту — `project_name`.
2. Далі формуються вихідні файли в каталозі `src/`.
3. Після цього створюються конфігурація `package.json` і збірковий скрипт `scripts/build.js`.
4. Потім готуються CI-скрипти `ci.sh` і `ci.bat`.
5. На завершення формуються GitHub Actions workflow-файл `ci.yml`.

## 5. Обробка помилок оркестратором `init`

Оркестратор `init` працює послідовно і після кожного кроку перевіряє статус виконання.

Якщо один з кроків завершується з помилкою:

- робота негайно зупиняється;
- не виконуються наступні кроки;
- виводиться звіт із описом: який крок впав, чому, і що потрібно виправити;
- загальний статус не оголошується як успішний без отримання PASSED від `check`.

## 6. Таблиця відповідності файлів ролям

| Роль | Шлях | Призначення |
|------|------|-------------|
| agent | `.github/agents/` | описує поведінку, обов'язки та правила роботи агента |
| skills | `.github/skills/` | формалізує логіку проєктування, збірки і CI |
| commands | `.github/prompts/` | містить prompt-команди для користувача та оркестратора |

## 7. Примітка про використання стандарту VS Code Copilot

Цей проект використовує стандартний підхід VS Code Copilot для роботи з агентами, навичками та prompt-файлами. Основна ідея — розділити логіку на окремі одиниці відповідальності: агент, навички, команди та документацію. Це дозволяє зберігати порядок, підвищувати повторне використання і робити процес автоматизації більш передбачуваним.
